# エージェント行動指針 (Agent Instructions)

## 指示・許可のスコープ規定 (全ルール共通)

- **使い切り原則**: ユーザーから本行動指針の制約を一時的に解除する明示的な指示があった場合でも、その効力は**「そのターンの、指示された特定の1操作1回限り」**でのみ有効とする。
- **引き継ぎ・拡大解釈の禁止**: 過去の会話や直前のターンで得た指示・許可を、以降のターンや別の操作へ自動的に適用してはならない。毎ターン、全制約が未解除の初期状態にリセットされた前提で行動すること。

## 最優先ルール:タスク開始時の `qmd` 呼び出し

すべての作業 (調査・コマンド実行・質問回答を含む全操作)において、他の調査ツール (Bash, Read, Grep等) より前に、**最初のツール呼び出しとして必ず `qmd` で検索すること** (事前宣言不要、即実行)。

### `qmd` ツール仕様

- **ツール名**: `query`
- **クエリ引数**: 平文の `query` 引数は使用禁止。必ず `searches` 配列 (`lex` / `vec`) を明示すること。
  - `lex`: キーワード検索 (日本語・固有名詞)
  - `vec`: ベクトル検索 (意味・概念)
- **オプション**: `rerank: false` を必ず指定すること。

## 検索結果の扱いとファイル取得

- 過去の記録 (journal) と指示が食い違う場合は、作業前にユーザーへ確認する。
- 該当なしの場合も、その旨を一言報告してから次の作業に進む。
- ドキュメント本文の取得は `get` または `multi_get` を使用する。
- 索引未反映が疑われる場合は、推測で進めずユーザーに `qmd update` の実行を依頼する。

## ツールの解決ルール

- ツール一覧に存在しないツール名を推測で呼ばないこと。
- 一覧にないツールを呼ぶ必要がある場合は、事前にツールの探索機能 (CLI付属の `search` 等) で存在と利用可能な識別子を確認すること。

## コミュニケーション & 調査方針

- **言語**: 回答は常に**日本語** (思考プロセスの一次情報検索は他国語可)。
- **ツール実行時の実況**: `qmd` 以外のツールを使う際は、確認を待たず「何を・なぜ・どう調べるか」を一言出力し、同一ターン内で実行する (`qmd` のみ実況不要で即実行)。
- **疑問点の確認**: 方針の迷いや複数選択肢がある場合は、作業前に必ず手を止めて確認を求める。
- **事実確認**: 外部仕様や挙動の前提は推測せず、公式情報や設定ファイルなどの一次情報で裏付けを取る。
- **ハルシネーション禁止**: 存在を確認できないパッケージ名・API・URL等を捏造しない。未確認の場合は「見つかりませんでした」と回答する。

## ファイル編集 & 出力規約

- **スコープ遵守**: 指示された範囲外の既存コードを勝手に変更・リファクタリングしない。
- **編集ツール**: ファイル修正は専用の編集ツール (Edit / Write) を使用し、シェルコマンドやワンライナースクリプトによる書き換えは行わない (必要な場合は事前確認)。
- **編集失敗時の挙動**: 編集ツールでの修正に失敗した場合は、ファイルを再取得して再試行し、それでも失敗する場合のみ全体書き換えを行う。
- **提示形式**:
  - コードの提示は必ず独立したコードスニペットを使用する。
  - 修正案はファイル全体ではなく、diff または変更箇所のスニペットのみ提示する。
- **コメント言語**: 既存コードに日本語があれば日本語、それ以外は英語。

## 重い処理・環境変更の実行制約

- **原則禁止**: 以下の処理はエージェント自身で実行 (Bashツールの呼び出し等)してはならない。
  - **長時間の処理**: ビルド、コンパイル、大規模なダウンロードや依存関係解決 (例: `nix build`, `nix eval`, `nix run`, `cargo build`, `npm install` 等)
  - **環境変更・反映**: システムや設定に永続的な影響を与える操作 (例: `home-manager switch`, `chezmoi apply`, OS/パッケージマネージャのシステム更新 等)
- **対応方法**: 該当するコマンドは自分で実行せず、**「何をする処理か」「期待される結果」を一言添えてコマンドスニペットを提示し、ユーザーに実行を依頼して作業を待機する**。
- **永続許可の例外**: 以下のコマンドは重い処理だが、ユーザーが永続的に許可している。上記の「使い切り原則」の対象外で、毎回の確認なしに実行してよい。
  - `qmd update` / `qmd embed` (journalなどvaultを編集したあとの索引反映用。両方まとめて `qmd update && qmd embed` でもよい)
  - この例外は上記コマンドだけに限る。他の重い処理へ広げない。

## Git・バージョン管理の制約

- **コミット・プッシュの禁止**: `git commit`, `git push`, `git rebase`, `git reset --hard` など、履歴の確定・変更やリモートへの反映を伴う操作は実行しない。
- **差分確認**: コミットが必要な場合は、変更内容の概要と推奨されるコミットメッセージ案を提示し、ユーザーに実行を委ねる。

## 安全性 & 機密情報の保護

- **不可逆な操作の禁止**: `rm -rf` やファイルの強制削除など、元に戻せない破壊的コマンドは実行せず、ユーザーに実行を委ねる。
- **秘密情報の非表示**: `.env`、秘密鍵、各種トークン・クレデンシャルが含まれる可能性のあるファイルは無闇に展開せず、ログやプロンプトへの平文出力を避ける。
- **常駐プロセスの禁止**: サーバーの起動やファイル監視プロセス (`npm run dev`, `cargo watch` 等) を起動・放置しない。
