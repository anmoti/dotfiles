# Commit Changes

リポジトリの規約に合わせた適切なコミットメッセージを作成しつつ、必要な変更だけを細かい粒度（ファイル単位またはハンク単位の部分ステージング）で安全にステージングしてコミットします。

## Guidelines

- **明示的な指示がない限り既存コミットを変更（amend）しない**。
- **ユーザーの明確な承認なしに push や force-push を実行しない**。
- **pre-commit hooks をスキップしない**（`--no-verify` を使用しない）。
- **コミット署名をスキップしない**（`--no-gpg-sign` を使用しない）。
- **ユーザーの変更を取り消し・リセット・破棄しない**（明示的な指示がある場合を除く）。
- シークレット情報やビルド成果物など、誤ってコミットすべきでないファイルが含まれていないか確認する。
- ステージング対象やメッセージ内容に迷った場合はユーザーに確認する。

## Workflow

### Step 1 - リポジトリ規約の確認

直近のコミット履歴を確認し、メッセージ規約（Conventional Commits、プレフィックス、日本語/英語スタイル等）を把握します。

```bash
git log --oneline -20
git log --oneline --author="$(git config user.name)" -10

```

### Step 2 - 作業ツリーの状態と差分の確認

現在の変更状態を確認します。

```bash
git status -s
git diff

```

* 変更が何もない場合は、その旨を伝えて終了します。
* 既にステージされた差分が存在し、それをそのままコミットする場合は Step 5 へ進みます。

### Step 3 - ファイル単位のステージング

Step 2 で確認した差分のうち、ファイル全体をそのまま今回のコミットに含めてよいものをステージします。

```bash
git add <files>
git status -s

```

### Step 4 - ハンク単位の部分ステージング（必要な場合のみ）

同一ファイル内の一部変更だけをコミットしたい（細かい粒度で分割したい）場合はパッチ編集方式を使用します。
ファイル単位で完結している場合は Step 5 へ進みます。

1. 対象ファイルの未ステージ差分を一時パッチファイルに出力:

```bash
PATCH_FILE=$(mktemp)
git diff <file> > "$PATCH_FILE"

```

2. パッチファイルを編集して、今回のコミットに含めない変更を取り除く:

   * 含めないハンクは、`@@` 行から次の `@@` 行の直前までを丸ごと削除する。
   * 1つのハンクの一部の行だけ含める場合は、含めない `-` 行の先頭を半角スペースに変えて文脈行に戻し、含めない `+` 行は削除する。
   * ヘッダ（`diff --git` から `+++` まで）は消さない。

3. 適用できるか確認してから、インデックスにだけ適用する:

```bash
git apply --cached --recount --check "$PATCH_FILE"
git apply --cached --recount "$PATCH_FILE"
rm -f "$PATCH_FILE"

```

   * 適用後は Step 5 で、意図した変更だけがステージされているか確認する。

### Step 5 - ステージング内容の最終確認

コミット対象となったステージ済み差分を確認します。

```bash
git diff --cached --stat
git diff --cached

```

### Step 6 - コミットメッセージの生成とコミット実行

Step 1 で把握した規約と Step 5 のステージ済み差分をもとに、以下の要件を満たすメッセージを作成してコミットを実行します。

* 規約に準拠した要約行（Subject: 72文字以内）。
* 必要に応じた変更理由の説明（Body: 自明でない変更の場合のみ）。
* ブランチ名や文脈に含まれる関連イシュー・チケット番号の参照。

```bash
git commit -m "<subject>" -m "<body>"

```

- `error: 1Password: agent returned an error`と出た場合は、ユーザーがコミットを拒否しています。
   再実行やフラグ回避を行わず、コミットを中断してユーザーに報告してください。

### Step 7 - 完了確認

```bash
git status -s
git log --oneline -1

```

* pre-commit hooks によって自動修正やブロックが発生した場合は、その内容を正確にユーザーへ報告します。
* hooks によってファイルが書き換えられた場合、勝手に `amend` せず、追加コミットとして含めるかをユーザーに確認します。
